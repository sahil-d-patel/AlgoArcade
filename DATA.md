# Data

AlgoArcade has no dataset in the usual sense. Agents generate their own data by playing. What we do have is game data that is not ours to distribute, and a lot of logs.

> **`DATA.md` is tracked in git. The `data/` folder is not.** ROMs, save states, symbol files, logs and checkpoints stay on your machine. Clone the repo, then fill `data/` locally.

## What goes in git

Commit:

- our own code, tests, docs and experiment definitions;
- the hand-curated address table, with provenance;
- manifests that list hashes of files kept elsewhere;
- schematic map output drawn from collision data, if we decide to keep it in the repo.

Never commit:

- a ROM, a save file or an emulator save state;
- a symbol file, a `map.bin`, a tileset or anything else copied from the decompilation;
- a map rendered from the game's tile art;
- anything under `data/`, including logs, checkpoints and videos;
- secrets, API keys or `.env` files.

A pre-commit hook and a Claude Code hook both reject these by extension and by path. If one slips through, stop and tell a PM. Do not try to rewrite history yourself.

## Local layout

```
data/
├── roms/          # your own dumps
├── states/        # save states listed in the manifest
├── pokefirered/   # fetched symbol files and map data
├── runs/          # run_id=<id>/ with Parquet logs and checkpoints
├── videos/        # rendered clips
└── llm/           # transcripts and usage logs
```

This replaces the template's `raw/`, `interim/`, `processed/` layout. That layout fits a pipeline that cleans a dataset in stages, and we do not have one.

## Reproducibility

- Every run records its seed, git commit, ROM SHA-1 and a hash of its reward config. That is how we explain, weeks later, why two runs differ.
- Every headline claim uses five seeds, compared on the same seed set. Three-seed results are labeled exploratory.
- Hyperparameters live in code as typed configs. The resolved config is written into the run directory.
- Checkpoints are saved every 500,000 steps and kept until the showcase, so we can render video without retraining.
- Per-step logs are never deleted before the showcase. Visuals are built last, and anything we did not log is gone.

The logging schema is in [`docs/harness-spec.md`](docs/harness-spec.md). It freezes on November 1.
